# Pigmento — Plan

> **Pigmento** — *Paint simply. Create boldly.*
> A friendly raster editor for Windows 11 with the classic Paint layout and room to grow into layers, custom shapes and custom brushes.

This file is the source of truth for scope and progress. Each milestone has a checklist; tick items as they land (one commit per sub-step) so work can resume from here after a context reset.

---

## 1. Stack decision

| Concern | Choice | Why |
|---|---|---|
| Language | TypeScript 6.0 (strict) | Required. 6.0 rather than 7.x because `typescript-eslint` supports `<6.1`. |
| Desktop shell | Electron 45 | Needs only Node.js on Windows (no Rust/C++ toolchain). Native dialogs, clipboard, jump lists, title-bar overlay with Snap Layouts. |
| Build | electron-vite 6 + Vite 8 | One config builds main, preload and renderer, with HMR in dev. |
| UI | React 19 + Zustand 5 | React for the chrome only. Zustand mirrors engine state for React. |
| Engine | Plain TypeScript, no React | Unit-testable in Node. React talks to it through `Engine`'s typed API and events. |
| Rendering | Canvas 2D + Web Workers | CPU tiled surfaces hold the pixel data, GPU canvases mirror them for display, and workers decode, encode and flood-fill. The renderer interface can later be swapped for WebGL. |
| Validation | Zod 4 | Settings now; shape and brush packs later. |
| Icons | Lucide (ISC) + a few hand-drawn SVGs | Consistent 2px stroke icons, open license. |
| Font | Inter Variable via `@fontsource-variable/inter` (OFL-1.1) | Bundled, readable, no network. |
| GIF encode | `gifenc` (MIT) | Small, dependency-free quantizer and encoder. BMP is a hand-written encoder. |
| Tests | Vitest 5 (unit), Playwright 1.64 `_electron` (e2e) | As specified. |
| Packaging | electron-builder 26 (NSIS + portable) | As specified (Milestone 4). |
| Icons build | `@resvg/resvg-js` (dev only) | Rasterises the SVG logo to PNG/ICO with prebuilt binaries, no native toolchain. |

Security baseline: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, a typed preload bridge, a strict CSP (meta tag, production has no `unsafe-*`), a custom `app://` protocol in production instead of `file://`, blocked navigation and `window.open`, permission requests denied except `local-fonts` and clipboard-write, and all non-local network requests cancelled.

## 3. Core architecture

### 3.1 Engine/UI boundary
- The UI calls only `Engine` methods (`engine.setTool`, `engine.undo()`, `engine.image.rotate(90)`, …) and subscribes with `engine.on(event, fn)`.
- The engine emits typed events: `doc`, `history`, `view`, `selection`, `tool`, `live`, `cursor`, `colors`, `dirty`.
- Host services (files, clipboard, dialogs) live in the UI layer and call the preload bridge `window.pigmento`. The engine never touches IPC.

### 3.2 Document model
`Document { width, height, dpi, paper: RGBA | null, layers: Layer[], activeLayerId, selection }`
- `paper` is the canvas background colour, composited under every layer and exported unless transparent. The eraser, Delete and moving a selection reveal the paper (see Assumptions).
- `Layer` is the base type; Milestone 1 ships `RasterLayer` (`Surface` + opacity, blend, visible, locked). The model already has a layer list with blend and opacity, so Milestone 2 adds vector and group layers without changes to the core.
- **Live objects** (a shape being edited, a text box, a floating selection) belong to the engine rather than the document. They render above the active layer and rasterise into it on commit as a single history command.

### 3.3 Pixels: tiled surfaces
- `Surface` holds straight RGBA8 pixels in 256×256 tiles of `Uint8ClampedArray`. A `null` tile is fully transparent, so empty areas cost nothing.
- Edits go through `beginEdit()/endEdit()`. The first write to a tile captures its previous array (copy-on-write) and `endEdit()` returns a **TileDelta** containing only the tiles that actually changed.
- Each layer also has a doc-sized GPU **mirror canvas** that is only ever written with `putImageData`, never read back. This avoids GPU readback stalls.

### 3.4 History
- Command pattern: `{ label, undo(), redo(), bytes }`. A command is pushed after its action has already been applied.
- `TileDeltaCommand` undoes and redoes by swapping tile arrays, so one stored copy serves both directions. Self-inverse operations (flip, rotate 90/180/270) store no pixels. Size changes (crop, resize, canvas size) store the replaced surfaces.
- A memory budget (default 1 GB) evicts the oldest commands. The History panel lists the states and lets you click one to jump to it.

### 3.5 Rendering
- **Compositor:** a doc-sized composite canvas updated only inside dirty rectangles: clear, then each visible layer mirror with its blend and opacity, with the live object inserted after the active layer.
- **View:** a screen-sized canvas showing the workspace background, the document shadow, a checkerboard (fixed screen size) and the composite under the view transform. Smoothing is off at 200% and above (crisp pixels). The pixel grid appears at 800% and above.
- **Overlay:** a separate canvas for marching ants, handles, the brush cursor, previews and grid lines. It never touches pixel data.
- High-DPI: canvas backing stores use `devicePixelRatio` and re-size when it changes (per-monitor DPI).

### 3.6 Tools (plugin interface)
```ts
interface Tool {
  id; labelKey; icon; shortcut?; group; order;   // placement in ribbon is data-driven
  cursor(ctx): CursorSpec;
  getOptionsSchema(): OptionSpec[];               // options bar renders from this
  onActivate?/onDeactivate?;
  onPointerDown/Move/Up(e: ToolPointerEvent, ctx: ToolContext);
  onKeyDown?(e, ctx): boolean;
  renderOverlay?(ov: OverlayContext, ctx);
}
```
Tools live in `engine/tools/builtin/*.ts` and register themselves. `import.meta.glob` loads every file, so adding a tool means adding one file.

### 3.7 Input
Pointer Events with `getCoalescedEvents()`, pressure and tilt, and the pen eraser end (`buttons & 32`) temporarily switching to the eraser. Touch is ignored while a pen is down (palm rejection). Two-finger touch pinches to zoom and pans. Middle mouse or Space+drag pans, Ctrl+wheel zooms at the cursor, Shift+wheel scrolls horizontally.

### 3.8 Main process and storage
- User data lives in `%APPDATA%\Pigmento\` (overridable with `PIGMENTO_USER_DATA` for tests): `settings.json`, `recent.json`, and later `library/`, `autosave/`.
- Every write is atomic: write `*.tmp`, fsync, then rename, with a retry on Windows `EPERM`/`EBUSY`.
- A single-instance lock means "Open with" or the jump list sends the file to the running app, which opens a new window unless the current one is an untouched blank document.
- Native dialogs, clipboard (`nativeImage`), print (a hidden window holding the flattened PNG, then `webContents.print`), and wallpaper (PNG under AppData, then PowerShell P/Invoke `SystemParametersInfo`).

### 3.9 Registries
`ToolRegistry` (Milestone 1), then `ShapeRegistry` (Milestone 2), `BrushRegistry` and `FilterRegistry` (Milestone 3). All of them use Zod schemas, and built-in and user items go through the same registry and schema.

## 4. Assumptions and decisions
1. **Name and brand:** Pigmento. Primary accent Ultramarine `#4B4BE0`, secondary accent Cadmium `#FF8A3D`. Native project file `.pigm`, brush pack `.pigmbrush`.
2. **Paper background:** each document has a paper colour (default white). Classic Paint paints the secondary colour when you erase or move a selection. Pigmento makes those pixels transparent on the layer, which reveals the paper. A beginner sees the same result, and it works cleanly with layers. Opened images get white paper if they are fully opaque, otherwise transparent paper, so alpha is preserved when saving.
3. **Text:** text boxes grow to fit (point text). New lines come from Enter, with no automatic wrapping, so the on-canvas preview and the rasterised result match exactly.
4. **Single document per window.** File > New/Open replaces the document after an unsaved-changes prompt. "Open with" while the app is running opens a new window.
5. **Native message box** for "Save changes?" prompts (Save / Don't save / Cancel), because it is the most Windows-native.
6. **Colours carry alpha.** Primary and secondary colours may be semi-transparent, set in Edit colours.
7. **Ribbon tabs appear when they have content.** Milestone 1 ships Home, Image and View. Shapes, Brushes and Effects arrive with their milestones, per the "nothing unbuilt in the UI" rule.
8. **Saved palette files** (.json/.gpl/.ase import and export) land in Milestone 2. Milestone 1 has the built-in palette, recent colours and "Add to custom colours", persisted in settings.
9. **SVG export** lands in Milestone 2, when vector objects can export as real paths. Raster-only SVG adds little.
10. **Wallpaper:** the implementation is tested with a read-only `SystemParametersInfo` query, so development and tests never change the real desktop.
11. **Help and About** are allowed earlier than Milestone 4 if they are complete. The full shortcut editor stays in Milestone 4, but every shortcut already goes through the action registry.
12. **Eraser** makes layer pixels transparent (reveals the paper). More eraser variants arrive in Milestone 3.

### Milestone 5 — Animation mode (requested after 1.0)
Keyframe animation of pieces cut from a selection (move, rotate, scale, stretch, skew, fade, curved motion paths, movable pivot), frame-by-frame drawing with onion skin, and export to animated GIF and MP4. Split into four stops; each ends with a working app, `npm run check` green and a report, then waits for "continue". Each item is ticked in the same commit as its work.

Words used in the UI: the **timeline** (fps 1–60, default 12; length 1–2000 frames, default 24; loop, once or ping-pong), a **piece** (pixels lifted from a selection on a pixel layer, drawn just above that layer's pixels and inside the layer), a **keyframe** (position, scale X/Y, rotation, skew, opacity, easing to the next keyframe, optional motion-path handles; held before the first and after the last; rotation isn't wrapped), the **pivot** (what a piece turns and scales around; moving it never moves the piece), and a **cel** (one drawing of a frame-by-frame layer, shown from its start frame until the next cel).

Decisions: pieces come only from pixel layers; shape layers and text aren't frame-by-frame; pieces are cut-outs (animated, not repainted); animation is Full mode only; MP4 has no sound.
